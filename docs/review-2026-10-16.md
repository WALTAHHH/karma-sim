# Karma Simulator: Full Review, 2026-10-16

Sources:
- A hands-on play at phone size (375x812).
- Six review passes: game-designer, ui-ux, mobile-reviewer, unity-architect, art-director, and a bug-hunt/simulation pass.
- Headless simulations of 5,000–10,000 lives using the game's real JS modules, run in Node.

Each issue lists its severity, which reviewers found it, and where in the code it lives. Issues found by several reviewers are merged into one entry.

Severity: **C** = Critical, **H** = High, **M** = Medium, **L** = Low.

## Platform: stay web or go Unity/Blender?

**All six reviewers say: stay web.** Ship as a PWA, then wrap it with Capacitor (iOS + Android) or a TWA (Android only) if you want it in the app stores.

| | Stay web + wrap | Port to Unity |
|---|---|---|
| Effort (architect estimate) | **~6–10 person-weeks** (fixes + mobile hardening + PWA + Capacitor) | **~25–37 person-weeks** for parity |
| Keeps | Live URL, instant updates, <2 MB install, CSS-speed text layout, accessibility | n/a |
| Gains | App-store presence cheaply | Physics2D for the minigames, Unity ads/IAP/analytics, Factory agents and pipeline |
| Loses | Factory Unity tooling doesn't apply | The web build (Unity WebGL on mobile is poor), iteration speed, a 20–60 MB install |
| Blender | n/a | Adds nothing: the identity is ASCII + 2D cards |

Why:
- The game is text and choices.
- The core logic (~2.6k lines) already has no DOM dependency.
- None of the problems below is an engine limit. They are design, layout, input, and timing bugs.

**What would flip it to Unity:**
1. The creative direction moves to 3D or animated presentation.
2. Canvas minigames can't hold the frame-rate target on the minimum Android device even after the fixes below. Try PixiJS for the minigames before porting.
3. You need monetization beyond what Capacitor plugins cover.
4. You decide every Factory title must run on the shared Unity pipeline.

**No-regret first step either way:** move the content (137 events, 101 jobs, 181 countries, eras, tags, achievements) out of JS literals into validated JSON, and add seeded "golden" tests. That makes any later port mostly a UI rebuild.
